# v0.1.0 — 跨会话通信插件（首个版本）

> 让同一个 DSH 进程里的会话**互相读、互相发消息**，且**不改变目标会话的 agent preset 与模型**。
> 为「QQ 机器人当调度器、把活派给工作区里已有会话」这套玩法提供底层通道。

## 安装

```bash
# 从 release 资产装（不用 clone）
dsh plugin --profile web add \
  https://github.com/ZinChl/dsh-session-link/releases/download/v0.1.0/dsh-session-link-0.1.0.tgz

# 或从仓库装
dsh plugin --profile web add github:ZinChl/dsh-session-link

# 装完重启 dsh（profile 变更是 restart-required，刷新页面不算）
dsh web
```

装完**所有会话自动获得**五个工具，不需要改任何 agent preset。
资产随附 `SHA256SUMS`，可用 `sha256sum -c SHA256SUMS` 校验。

> ⚠️ npm 上有同名包（`dsh-session-link@0.2.x`，作者 PwnKY，功能是会话深链），与本项目无关。
> 本项目**不发布 npm**，请用上面的 release 资产或仓库地址安装。

## 五个工具

| 工具 | 作用 |
|---|---|
| `session_list` | 列出**已存在**的会话：id / 标题 / cwd / live / running / **archived** / 最近活动 / agent preset |
| `session_read` | 读取某个会话的**有界**近期内容（只读快照，标出哪些消息来自本插件） |
| `session_send` | 投递一条消息并唤醒目标（`followup` / `steer` / `inject`） |
| `session_ask` | 投递并**等对方这一轮结束**，把回复文本带回来（会话间 RPC） |
| `check_delivery` | 按 `requestId` 查回执：delivered → claimed → completed，或拒绝原因 |

## 硬保证

1. **不新建会话** —— 只读已有 + 写已有；代码里没有 `agents.create`（有测试盯着）。
2. **不改变目标会话的能力集** —— 冷会话恢复时 `agentOptions` / `setup` **只取目标自己的持久化记录**；
   恢复前后各探测一次，preset 或模型路由漂移就回滚拒绝（`CAPABILITY_DRIFT`），目标 preset 解析不出来也拒绝而不降级。
3. **归档会话拒绝投递且不唤醒**（读 `workspaceRegistry.archivedSessionIds` 全局集合）。
4. **拒绝发给自己**；**同进程**，无网络传输。
5. **投递内容不可信** —— SLEP v1 信封：可信前导 + 不可伪造的 `<agent_message>` 边界，
   正文里的边界标记会被转义；信封带 `thread` / `hop` / `request_id` 供对等回信。
6. **跳数预算**（默认 6）—— 两个 agent 互相唤醒会被掐断，不会无限对轰。
7. **幂等**（`requestId` + 正文指纹）、**限流**（每对会话 12/分钟）、**审计**（NDJSON 一行一决策，可重放）。
8. **优雅降级** —— 缺 `sessionQuery` / `agents` / `agentPresets` / `workspaceRegistry` 时返回可读说明，不抛裸异常。

## 验证

- **120 个离线单测**（`node --test`，零运行时依赖）；
- **真机端到端**（真进程、真模型、真会话文件）：冷会话恢复唤醒、A→B→A 回信（跳数 1/6 → 2/6）、
  能力守卫（`preset standard → standard`、`model deepseek-v4-pro → deepseek-v4-pro`、`drift=false`）、
  归档/自激/steer-on-idle 拒绝、幂等重放、回执时间线；
- 完整原始输出与排查过程见 [`docs/verification.md`](https://github.com/ZinChl/dsh-session-link/blob/main/docs/verification.md)；
- 真机测试过程中发现并修复了 4 个只有端到端才能暴露的 bug（详见 CHANGELOG）。

## 已知限制

- 只服务**同一个 DSH 进程**内的会话；无跨主机/网络传输、无多播。
- `steer` / `inject` 需要目标正在运行，空闲目标会被明确拒绝（有意不静默降级为 `followup`）。
- 会话特别大时 `session_read` 需要物化一次事件数组（宿主侧有观测缓存）。
- 标题在批量接口不可用时逐个读取，可能变慢（会在 `degraded` 里说明）。
- 回执状态 `claimed` / `completed` 由插件订阅宿主的会话事件推进；进程重启后只剩落盘的部分。
