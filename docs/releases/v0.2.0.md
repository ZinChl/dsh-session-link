# v0.2.0 — Web 设置页：跳数可调，保存即生效

> 在 v0.1.0（跨会话通信 + 信封协议 + 能力守卫）之上，加了一个**真正在 Web UI 里的设置页**：
> 不用改 profile、不用重启 dsh，直接在侧边栏把跳数上限等参数改掉。

## 新增：设置页

**侧边栏 → Plugins → dsh-session-link → 配置**

![设置项](https://github.com/ZinChl/dsh-session-link/raw/main/icon.svg)

| 字段 | 默认 | 说明 |
|---|---|---|
| **跳数上限 `maxHops`** | 6 | 一条线程 A→B→A→B… 允许的最大跳数，超过就拒绝继续转发（1–64） |
| 限流 `rateLimitPerMinute` | 12 | 每对「发送方→接收方」每分钟最多投递几条，0 = 不限流 |
| 去重窗口 `dedupeWindowMs` | 300000 | 相同内容在这个窗口内不会重复投递 |
| 正文上限 `maxTextChars` | 8000 | 单条消息字符上限 |
| 能力守卫 `verifyCapability` | true | 投递前后校验目标的 preset/模型是否漂移 |
| 审计文件 `auditFile` | `~/.dsh/session-link/audit.ndjson` | 回执与审计文件路径 |

每个字段旁边显示「默认 N」和「已覆盖」标记，可以逐项**恢复默认**。

**保存立即生效**：宿主 settings 对这个条目的 `applies` 是 `live` —— 写入后加载器会重新激活条目，
`apply()` 带着新配置再跑一遍（审计文件按 revision 重放，回执不会丢），不需要重启 dsh。

## 实现要点（给维护者）

- 宿主侧 `lib/config.js` 声明字段（范围 + 中文描述），`lib/index.js` 导出 `Config`；
  没有 schema 的条目在设置页里没有可编辑字段，所以这一步是前提。
  **关键细节（踩了四轮才定位）**：宿主只为「Config 里标了 `.volatile()`」的字段建立设置命名空间
  （`dsh-settings` 的 `volatileForm()` 只投影 `meta.volatile`；一个 volatile 字段都没有的条目**根本不进**命名空间列表）；
  `.volatile()` 是 `@deepseek-ai/schemastery`（DSH fork）的方法，npm 包没有 —— 所以它缺席时直接写
  `meta.volatile`（宿主只读这个标记）；volatile 值解析出来是 `{ get() }` 包装对象，
  插件在 `resolveConfig()` 里统一解包。
  第四轮的原因跟代码无关：**运行中的 `dsh web` 起得比修复早**，Cordis 缓存了已 import 的模块，
  宿主手里那份 `Config` 仍然一个 volatile 字段都没有 —— 改完 `lib/` 必须重启 dsh，刷新页面不换代码。
- 不用浏览器也能自检「新进程会不会给设置页」：`npm run probe:settings`（加 `--write` 再验保存路径）。
  它把一次性 overlay 插件塞进 `dsh --profile headless --patch <临时文件>`（不写 prompt、不调模型），
  让那个进程里宿主自己的 `ctx.settings.describe()` 汇报本条目；真机输出见
  [docs/verification.md](../verification.md#411-设置页v020命名空间可编辑字段保存路径)。
- 浏览器侧 `lib/client.js` 是**纯 JS 客户端模块**（`window.__ModuleLoader__.load`），
  注册进键控槽 `plugins.bundle.config`，key 就是包名；读写走 settings 域自己的客户端服务
  `ctx.configForms`（`describe()` 的镜像快照 + `mutate(ops, revision)`），
  并订阅 `settings/document-updated` 让表单跟随外部改动刷新。
- 家规遵守：不 import 任何 Harness Client 包，控件自己写，样式只用 `--dsw-alias-*` 主题令牌；
  槽注册用 `ctx.slots.inject(ownerKey, () => register(...))`，随槽的声明/拆除自动收放；
  宿主答不上来时组件渲染一行说明而不是抛错（抛错会让整个槽空白）。
- `schemastery` 是唯一的运行时依赖，且**容错加载**：解析不到时插件照常挂载，只是没有 schema 校验与设置页。

## 兼容性与修正

- **npm 安装修好了**：之前 `npm install` 会崩在 arborist（npm 默认自动安装 peer，
  而 npm 上 `@deepseek-ai/dsh-*` 只有 `0.1.0-rc.6` 这种远古版本）。现在所有 `@deepseek-ai/dsh*` peer
  都标记为 optional（它们本来就只由宿主提供）。
- CI 增加 `npm ci`，`check-manifest` 增加客户端半边校验（`dsh.client` 声明、`./client` 走
  `__ModuleLoader__.load` 且 id 等于包名、locale 元数据、图标导出、以及文件是否进得了 tarball）。
- 离线单测 141 个（Config schema 用例覆盖默认值、边界拒绝、描述齐全、可序列化，外加两个钉住
  「volatile 字段集合恰好是设置页那六个」与「拿不到 fork 时用 `meta.volatile` 兜底」的回归用例；
  另有 7 个浏览器半边用例用一个最小 React 替身跑组件，覆盖三条数据源分支与保存按钮的启用条件）。

## 安装 / 升级

```bash
# 新装
dsh plugin --profile web add \
  https://github.com/ZinChl/dsh-session-link/releases/download/v0.2.0/dsh-session-link-0.2.0.tgz

# 从 0.1.x 升级（link/路径安装同理换成新路径）
dsh plugin --profile web remove dsh-session-link
dsh plugin --profile web add <上面的地址>
# 重启 dsh：新增了浏览器半边，模块图需要重新扫描
dsh web
```

资产随附 `SHA256SUMS`。装完在侧边栏 **Plugins** 里能看到 dsh-session-link 卡片，
进它的页面就是设置表单。

## 已知限制

- 设置页只覆盖上面六个字段；其余参数仍走 profile 的 `cordis.patch.yml`（两条路写的是同一份用户层配置）。
- 新增浏览器半边后**需要重启一次 dsh** 才能被客户端模块系统扫描到（纯代码改动同样受模块缓存影响）。
- **任何 `lib/` 改动都要重启 dsh**：Cordis 缓存已 import 的模块，页面刷新不会换代码；
  设置页空白的头号原因就是这个（其次才是 patch 行缺失/被禁用）。
- 表单文案当前按浏览器语言在插件内切换中/英，没有接入 Client locale 服务（后续可迁移）。
